# 중복 프롬프트 제거 실험 (2026-11-01)

후보를 적용하지 않는다. 대표 6문장 교차 비교에서 평균 18.3% 느려지고 추가 재시도와
문법 오류가 두 번 재현됐다. 19문장 모델 추론이나 전체 영상 시험으로 확대하지 않았다.
운영 프롬프트·모델·검증·재시도·CPU·메모리 설정은 변경하지 않았다.

2026-11-03 정리: 미채택 평가 도구·관련 테스트는 실행 경로에서 제거하고
[원문과 SHA256](retired-experiment-sources-261103.json)에 보존했다.
아래 명령과 테스트 수치는 당시 실행 기록이며 현재 실행 안내가 아니다.

## 변경한 실험 조건

기존 시스템 메시지에 기본 번역·숫자·부정·수학 관계·출력 지시가 있으므로 사용자
메시지의 동일한 기본 지시 사본을 제거했다. 문맥 안내 마지막의 중복 출력 지시도
제거했다. 나머지 문자열과 영어 원문·선택된 이전 문맥은 보존했다.
문맥을 사용자 메시지로 옮기는 과거의 접두부 캐시 후보를 반복한 실험이 아니다.

용어집은 기존에도 원문에 매칭된 용어만 포함한다. 이를 추가로 줄이지 않았다.
수식 표식·기호·나눗셈·함수 관계·정의·존댓말 지시·재시도 지시도 유지했다.
두 변경을 묶은 후보 하나의 결과이므로 각각의 중복 제거 효과를 분리한 결과는 아니다.

## 측정 결과

| 조건 | 첫 실행 | 두 번째 실행 | 평균 | 한 실행의 생성 시도 |
| --- | ---: | ---: | ---: | ---: |
| 기존 | 23.462초 | 25.995초 | 24.728초 | 6회 |
| 중복 제거 | 29.267초 | 29.226초 | 29.247초 | 8회 |

순서는 기존 → 후보 → 후보 → 기존이다. 각 실행은 같은 6문장을 같은 순서로 재생했다.
후보는 두 번 모두 두 기준 실행보다 느렸다. 각 조건의 반복 번역 출력은 동일했다.
24개 측정 번역 모두 최종 반환됐으며 실제 생성 시도는 28회였다.
측정 시간은 기존 번역 서비스의 HTTP 토큰화·생성·검증·재시도 전체를 포함한다.
모델 로딩·워밍업·업로드·STT·문장 묶기·자막은 제외한다.

| 입력 토큰 합계 / 실행 | 기존 | 후보 |
| --- | ---: | ---: |
| 첫 시도만, 캐시 포함 | 1,938 | 1,777 |
| 재시도 포함, 캐시 포함 | 1,938 | 2,359 |

첫 시도 입력은 8.3% 줄었지만 재시도까지 합치면 21.7% 늘었다.
이 입력 길이는 캐시를 포함한 전체 요청 토큰이며 실제 새로 계산한 토큰과 다르다.
후보의 첫 프롬프트 유출 응답은 스트림을 중도 취소하므로 최종 서버 시간 통계가 없다.
기준은 시도 6개 모두, 후보는 8개 중 7개만 서버 시간 통계가 있어,
부분 합계를 완전한 입력 처리·생성 시간으로 비교하지 않았다.
클라이언트 전체 소요 시간에는 취소와 재시도가 포함된다.

## 품질과 미채택 사유

- `rocket-2`: 후보의 첫 출력 `용어:`를 기존 검사에서 `prompt_leak`으로 거부했다.
  두 실행 모두 같은 재시도를 수행했다.
- `rocket-12`: 첫 출력은 `missing_math_division`으로 거부했다. 재시도 결과는
  `2m0로 나누어 줍니다 합니다.`로 끝났으며 두 실행 모두 같은 오류가 있었다.
  기존 문자열 검사를 통과했지만 수작업 검토에서 문법 결함으로 판단했다.

검사를 완화하거나 출력을 잘라 성공 처리하지 않았다. 테스트를 통과하거나
6문장 모두 반환됐다는 사실을 번역 정확도 향상으로 해석하지 않는다.
이번 후보의 실패가 모든 프롬프트 압축 방법의 불가능성을 뜻하지는 않는다.

## 환경과 검증

- Mac ARM64 Docker, VM 8 vCPU·약 6GB, 동일 공식 CPU llama.cpp 이미지.
- Qwen3-4B-Instruct-2507 Q4_K_M, SHA256은 원시 JSON에 기록한 기존 파일과 동일.
- CPU·추론 스레드 각각 8개, 번역 메모리·스왑 상한 각각 4GB.
- 기존 `--no-repack`, GPU·KV·연산 오프로딩 차단, 2,048 문맥,
  batch 256·ubatch 128·단일 슬롯·프롬프트 캐시 설정 유지.
- 각 실행은 새 독립 서버와 동일 캐시 비활성 워밍업을 사용하고 이후 캐시를 켰다.
- 운영 서버는 유지하고 별도 내부 네트워크에 평가 서버 한 개씩만 실행했다.
- 실행 전 활성 비동기 작업은 0이었다. 종료 후 두 운영 서버는 healthy였으며
  이미지·명령·자원·컨테이너 ID·실행 상태는 시작 전과 동일했다.
- 측정 중 OOM·재시작이 없었고 평가 컨테이너·네트워크를 정리했다.
- 동일 볼륨의 모델 파일 캐시를 운영 서버와 공유하므로 평가 cgroup 메모리는
  독립 실행 시 전체 메모리 요구량을 뜻하지 않는다.
- Windows AMD64, 발열·호스트 주파수 고정, 전체 영상 처리 시간은 검증하지 않았다.

관련 테스트만 실행했다.

```sh
.venv-api/bin/python -m unittest tests.test_prompt_dedup -v
```

6개 테스트 통과. 원문이 지시문을 인용해도 삭제하지 않는지, 수식·용어·재시도·문맥을
보존하는지, 기준 경로가 기존 운영 메시지와 같은지, 토큰 수 기록이 HTTP 요청을
추가하지 않는지 검사했다. 19개 저장 입력의 두 시도를 오프라인으로 검사한 것이며
실제 19문장 모델 추론을 실행한 것은 아니다. 전체 테스트 모음은 실행하지 않았다.
