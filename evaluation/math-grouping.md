# 수식 설명의 번역 단위 결합

검증일: 2026-10-18. 기본 Qwen 교체 커밋 `3d4b1d3` 이후 단계다. 기존 문장부호 기반 STT 묶음을 만든 다음 수학 설명의 명시적인 연결 단서가 있는 인접 항목을 함께 번역한다. 모델·용어집·프롬프트·최대 128토큰·재시도 정책은 변경하지 않았다.

이 문서는 존댓말 변경 전 수식 결합만 적용한 평가다. 이후 말투 지시를 추가한 결과는 [존댓말 검증 기록](formal-translation.md)에 별도로 기록했다.

## 동작과 보존 범위

- 상수 항의 위치 설명과 뒤 분수, 적분 시작점·초기 조건·끝점, 질량의 정정 설명, 식과 적분 결과, 함수 표기와 뒤 식을 연결한다.
- 여러 구간을 합칠 때 18초·350자 상한과 2초를 초과하는 무음 경계를 유지한다. 물음표·느낌표, 독립적인 다음 등식, 사람이 밖으로 이동하는 일반 문장을 수학 위치 설명으로 합치지 않는다.
- STT의 숫자·변수·연산어·마침표를 수정하지 않는다. `2 vR prime of t`의 2를 to로 고치거나 `u1`을 다른 식으로 복구하지 않는다.
- 첫 start·마지막 end와 원래 source_indices를 보존한다. 내부 merge_reasons는 평가 근거로만 사용하고 API 응답에는 노출하지 않는다.
- `group_segments`의 기본값은 이전 평가 재현을 위해 `merge_math=False`다. 실제 공통 API 파이프라인은 True를 전달한다. 재시작 후 새로 접수한 작업에 적용되며 이미 저장된 결과는 바꾸지 않는다.

이 결합은 영어 연결 표현에 기반한 보수적 규칙이며 일반적인 수식 파서나 음성 오류 교정기가 아니다. 신호가 없는 끊김은 남고, 같은 상한 안의 관련 설명을 묶어도 의미 보존이 보장되지는 않는다.

## 같은 강의 입력 비교

이전 36개 묶음에서 5곳을 결합해 26개 번역 단위를 만들었다. 원문을 순서대로 이어 붙인 문자열과 전체 원본 인덱스 순서는 이전과 동일하다. 실제 평가 결과에 각 새 단위의 original_group_ids를 저장해 36개 원래 단위와 대응시킨다. 원본이 줄어든 것이 아니므로 단위 개수만으로 품질 개선율을 계산하지 않는다.

| 시간(초) | 함께 번역한 설명 |
| --- | --- |
| 47.0–58.56 | 상수 u → 앞에 놓음 → dmR/mR |
| 76.4–94.12 | v0에서 시작 → 초기 조건 → 불명확한 끝점 |
| 94.12–111.6 | m0 → 정확히 m0가 아님 → 2m0 설명·확인 |
| 127.4–141.32 | 식 → 적분 결과 ln → ln 확인 |
| 156.89–171.65 | vR(t) 언급 → 최종 식 |

Mac MLX에서는 26개 모두 번역을 반환했고 시도 수 27회·번역 합계 40.29초였다. 기존 MLX 기록은 36개 중 35개 반환·39회·52.81초다. 새 실행은 저장 STT 재생이며 로딩·음성 인식·HTTP 전체 시간은 포함하지 않는다. 단일 측정으로 속도 개선율을 일반화하지 않는다.

실제 출력에서 기존 `그는 앞서 나온다`가 `이를 앞쪽에 놓는다`로 바뀌었다. 이전 번역 미제공 구간 stt-25도 적분 설명과 함께 번역됐다. `vR of t`도 `t에 대한 vR`로 제공됐다. 반면 `dvR = u`처럼 원문에서 끊긴 등식은 그대로 불완전하고, `2 vR 프라임 of t`, 어색한 질량 정정 표현과 로그 괄호 범위도 남는다. **26개 반환을 26개 의미 정답으로 해석하지 않는다.**

Mac 실행·원시 시도: [최종 보고서](qwen-math-grouping-mlx-261018.json). 기존 비교: [Qwen API 적용](qwen-api-adoption.md).

## 검사와 재현

관련 테스트 62개를 통과했다. 수식 결합 8개·기존 자막 묶음 9개·업로드 파이프라인 23개·API 계약·평가 도구·변경 테스트 선택기를 포함한다. 실제 업로드 경로에서 결합된 문장을 한 번 번역하고 합친 시각·다음 문맥을 전달하는지도 검사했다. 전체 테스트 모음은 실행하지 않았다.

```bash
HF_HUB_OFFLINE=1 HF_HUB_DISABLE_IMPLICIT_TOKEN=1 TOKENIZERS_PARALLELISM=false .venv-api/bin/python scripts/evaluate_api_translation.py --backend mlx --model models/qwen3-4b-instruct-2507-4bit --merge-math --evaluated-on 2026-10-18 --output evaluation/math-grouping-new-run.json
```

`--merge-math`를 빼면 과거 36구간으로 재현한다. 새 출력 경로를 지정하며 이전 보고서는 덮어쓰지 않는다. CPU 재현은 llama-cpp 바인딩이 있는 환경에서 `--backend llama-cpp`와 고정 Qwen GGUF 경로를 사용한다.


## CPU 및 원본 정렬 확인

고정 Qwen GGUF Q8_0·Apple Silicon 네이티브 CPU 4스레드에서도 같은 조건을 실행했다. 26개 중 25개 반환·1개 실패, 27회 시도·번역 합계 108.54초였다. 실패는 이전과 같은 원래 stt-23이며 두 시도의 외국 문자 혼입을 거부했다. 기존 CPU 기록은 36개 중 35개 반환·155.70초였다. 단일 실행·개발용 같은 강의이며 Windows 속도나 의미 정확도 지표가 아니다. [CPU 원시 결과](qwen-math-grouping-cpu-261018.json)에 원본 ID·시도·거부 사유를 보존했다.

두 최종 보고서 모두 현재 결합기의 start·end·text·source_indices와 정확히 일치하고, original_group_ids를 이어 붙이면 stt-0부터 stt-35까지 중복·누락 없이 대응하는지 확인했다. 수식 위치 단서를 사람이 이동하는 문장과 구별하도록 좁힌 마지막 보완도 이 강의의 결합 입력을 바꾸지 않았다.

후속 과제는 STT의 2/to·함수 인자·끊긴 등식 확인과 수식 의미 검수다. 해당 부분을 결합만으로 해결했다고 보고하지 않는다. 변경을 적용하려면 서버를 재시작하고 파일을 다시 업로드한다.

최종 Windows용 Linux x86 CPU 이미지도 증분 빌드했고, 이미지 안에서 수식 결합 테스트 8개를 통과했다. 새 STT 실행이나 모델 가중치 변경은 수행하지 않았다.
