# 로켓 강의의 수식 경계·관계 보존 회귀 확인

2026-10-25. [사용자가 제공한 API 결과](rocket-api-result-261025.json)를 그대로 보존했다. 21개 항목은 이미 묶인 API 출력이며 원본 STT 39조각이 아니다. 이를 원본 STT 재인식 시험으로 해석하지 않는다.

## 변경

- 기본 18초·350자 문장 묶기는 유지한다. 뒤 단계에서 명확한 미완성 수학 발언만 최대 36초·350자 안에서 연결한다. 종결 문장·다음 질문·2초 초과 무음·시간 및 문자 상한을 보존한다.
- 사용자 결과에서 `[3,4,5]`, `[14,15]`, `[19,20]`을 각각 연결해 21개 항목이 17개가 됐다. `is a / constant`, `we can / immediately`, `our initial / velocity`가 더 이상 다른 번역 입력에 놓이지 않는다. 모든 원문·원본 인덱스와 첫 시작·마지막 종료 시각을 유지한다.
- `m of vR`와 `dmR over mR` 같은 지원 기호의 관계를 추출해 프롬프트에 함수·분수 예시를 안내한다. 입력을 고치거나 적분을 풀지 않고, 불명확한 로그의 분자를 추론하지 않는다.
- 검증기는 기호의 존재 외에 함수 이름·인수, 분수의 항·방향을 검사한다. `m(vR)`·명시적인 한국어 함수 표현, 슬래시·LaTeX 분수·`분의`·나누기 표현을 지원한다. 분모가 먼저 나오는 `m으로 나눈 u1`도 허용하며 소수·천 단위·부호의 같은 값 표기를 비교용으로 정규화한다. 실제 번역문을 자동 치환하지 않는다.
- 기존 문맥 제거 재시도·시도 상한 2회·출력 128토큰·2048토큰 검사·숫자·단위·존댓말 검사는 유지한다. 동기 파일 API와 작업 API가 공유하는 파이프라인에 적용한다.

## 관련 테스트

구현 파일에 연결된 단위 테스트 **138개 통과**. 전체 테스트는 실행하지 않았다. 기본 시간·문자 경계, 원문과 시각 보존, 함수의 곱셈 오역·인수 역전, 분수 방향·손실과 한국어 표현, 수치 표기 동치, 기존 파이프라인·작업·취소·HTTP 계약을 확인했다. 기존에 통과한 12번 함수 곱셈 출력과 14번 나눗셈 손실 출력은 새 검사에서 각각 `missing_math_function`, `missing_math_division`으로 거부된다.

## 실제 CPU 모델 확인

Mac ARM64, Docker VM 약 4.11GB, 기존 Qwen3-4B-Instruct-2507 Q4_K_M CPU 서버에서 문제 입력 5개를 재생했다. 새 프로젝트 모듈은 **별도 Python 프로세스에 로드**했고 실행 중인 backend API 프로세스·이미지를 교체하지 않았다. [채택한 코드의 출력·프롬프트·서버 시간](rocket-math-model-adopted-261025.json)을 보존했다. 기반 HTTP 서비스·용어집 파일의 실제 컨테이너 해시와 작업 트리 일치도 확인했다.

5개 중 **4개 반환·1개 실패**이며 의미 정확도 80%라는 뜻이 아니다. 일반 수학 파서·대수적 동치 판정·부정 및 등식 전체의 의미 판별까지 구현한 것이 아니다. 새 검증에 걸리면 잘못된 결과를 그대로 반환하는 대신 실패 구간이 증가할 수 있다.

마지막 실제 모델 호출 이후에는 숫자 표기 동치 처리만 보완했다. 최종 코드로 모든 저장 프롬프트와 시도별 검증 결정을 다시 계산해 실제 기록과 일치함을 확인했고 소스 해시와 함께 JSON의 `final_code_revalidation`에 명시했다. 숫자 보완 후 모델 생성을 반복하지 않았으며 해당 변경은 단위 테스트로 확인했다.

첫 후보의 [실제 출력](rocket-math-model-261025.json)은 올바른 분모 우선 한국어를 거부한 기록을 포함한다. [추가 함수 재시도 지시 후보](rocket-math-model-final-261025.json)는 함수 오류를 해결하지 못하고 복합식도 실패해 채택하지 않았다. 두 기록은 `audit.adopted=false`와 사유를 남겨 원시 출력·시도를 보존한다.

새 STT 추론·영상 전체 처리 시간·Windows 실기기·완성 Docker 이미지의 실제 API 호출은 이번 단계에서 검증하지 않았다. 선택 입력의 시간을 기존 167.111초 요청 시간에서 빼거나 전체 영상 속도 개선으로 환산하지 않는다. 실행 중 서버에 적용하려면 `docker compose up -d --build backend`로 이미지를 갱신해야 한다. 커밋·push는 수행하지 않았다.
