# 축약형 검증·공통 지시 캐시 최적화

2026-10-24. 변경 범위는 번역 검증기의 영어 축약형 처리와 Qwen 프롬프트 배치다. STT 모델 수명·Docker VM 메모리·모델·엔진·스레드·생성 설정·API 응답 형식은 바꾸지 않았다. 커밋·push는 수행하지 않았다.

## 구현

- `I'm`·`don't`·스마트 아포스트로피 축약형의 접미사를 수식 변수에서 제외한다. 따옴표 속 변수·프라임·한국어 조사·숫자·단위·수식 누락 검사는 유지한다.
- 긴 공통 지시를 시스템 메시지의 고정 접두부에 두고, 그 뒤에 이전 영어 문맥의 마지막 256자를 넣는다. 사용자 메시지에는 짧은 번역·보존·출력 전용 요청, 원문별 기호·용어와 현재 원문을 넣는다. 긴 공통 지시의 내용은 삭제하지 않았다.
- 두 번째 시도의 문맥 제거와 검증·시도 한도는 유지한다. 실제 수식 실패는 계속 재시도한다.

## 동일 3문장 비교

Mac ARM64 네이티브 Docker, VM 4,106,604,544 bytes, 동일 Q4_K_M 모델·동일 translator 컨테이너·CPU 4스레드·슬롯 1·컨텍스트 2048·GPU 오프로딩 0·`--no-repack` 조건이다. 별도 측정 프로세스에 STT Small CPU INT8 가중치를 유지했지만 STT 추론은 실행하지 않았다. 조건별 동일한 캐시 없는 워밍업은 합계에서 제외한다. 각 후보에서 캐시 끔→켬 순으로 한 번씩 측정했다.

| --- | ---: | ---: |
| 캐시 끔·3문장 합계 | 23.89초 | 21.92초 |
| 기본 캐시 켬·3문장 합계 | 13.31초 | 7.30초 |
| 캐시 켬·시도 수 | 3 | 3 |

기본 캐시 조건에서 합계가 **약 45.2%** 감소했다. 속도 문장·적분 문장은 변경 전후 같았고, 질량 문장은 `2m0`와 `2 m0`의 공백 차이만 있었다. 캐시를 끈 최종 후보도 세 문장 모두 첫 시도에 통과했다. [변경 전 원시 결과](cpu-prefix-before-261024.json), [채택한 후보의 원시 결과](cpu-prefix-request-261024.json)에 프롬프트·원시 출력·서버 시간·구현 해시를 보존한다. 원문·문맥·입력 해시 일치와 최종 이미지 소스 해시 일치를 확인했다.

각 후보의 순서·열 상태·파일 캐시 상태를 무작위화하거나 반복하지 않았다. 첫 문장은 워밍업과 문맥이 같아 재사용량이 많다. **짧은 3문장 결과를 이전 5분 영상 전체의 감소율이나 Windows 처리 시간으로 환산하지 않는다.**

## 이전 실패 구간·API 확인

[이전 5분 실측](cpu-arm64-5min-prompt-cache-261022.json)의 실패 구간 23·24·25·30번 원문과 직전 원문 문맥을 그대로 재사용했다. 네 구간 모두 첫 시도에 번역을 반환했고 합계는 18.38초였다. 이전 영상 처리의 두 번째 시도 합계 152.23초와는 STT 추론 후 메모리 상태·요청 이력이 달라 직접 차감해 전체 영상 시간을 추정하지 않는다.

나눗셈·부정·프라임·질문을 더한 8개 사례는 최종 검증 실패가 없었다. 나눗셈은 첫 출력에 영어 `over`가 남아 기존 검사로 거부했고 두 번째 출력의 `dmR / mR`를 반환했다. [8개 사례의 원시 출력·재시도](cpu-prefix-quality-request-261024.json)를 보존한다.

**검증 통과는 의미 품질 합격이 아니다.** 25번 구간에서 수학의 `origin`을 `원점` 대신 `기원`으로 옮겼고 `recitation`의 의미도 느슨하게 번역했다. 이 문제는 이번 성능 변경에서 수정하지 않았다. 독립적 의미 채점·장시간 품질 판정도 하지 않았다.

실제 `POST /api/v1/translations`에서 축약형과 나눗셈 입력 두 개 모두 HTTP 200을 확인했다. [API 결과](cpu-prefix-api-261024.json)에 응답·경과 시간을 보존한다. API 확인 때 공유 STT 모델은 미로딩 상태였으므로 STT 상주 비교의 성능 수치로 사용하지 않는다.

관련 파일에 연결된 단위 테스트 **76개**를 통과했고 전체 테스트는 실행하지 않았다. 축약형의 가짜 변수 지시·불필요한 재시도 방지, 실제 변수·프라임 보호, 공통 지시 위치, 용어·문맥 분리, 숫자·수식·존댓말·HTTP 오류 처리·파이프라인 계약을 확인했다. 최종 컨테이너의 OOMKilled는 false, 재시작 수와 cgroup OOM 카운터는 0이었다. 호스트 전체 RAM 최고치를 새로 측정한 시험은 아니다.

## 채택하지 않은 중간 후보와 남은 작업

`cpu-prefix-after-261024.json`·`cpu-prefix-quality-261024.json`은 사용자 메시지에 짧은 번역 요청이 없던 초기 후보다. `cpu-prefix-final-261024.json`·`cpu-prefix-quality-final-261024.json`은 짧은 번역 문장만 남겼던 두 번째 후보다. 두 후보에서 `용어:` 유출 또는 중복 어미가 관찰돼 채택하지 않았으며 각 JSON의 `audit.adopted=false`로 표시했다. 파일명의 `final`은 채택 여부를 뜻하지 않는다. 최종 채택 결과는 위의 `request` 파일들이다. 중간 출력·시간은 삭제하거나 덮어쓰지 않았다.

STT 종료 후 모델 메모리 해제, VM 6GB 비교, 변경 후 5분 영상 전체·Windows 실기기 속도, 호스트 7GB 목표는 남아 있다. 이번 작업으로 검증 완료라고 표시하지 않는다.
