# 챕터 생성 구현·검증 기록 (2026-11-12)

로컬 Qwen3-4B-Instruct-2507 Q4_K_M을 기존 HTTP 전송으로 호출하는 챕터 모듈과
저장 자막 평가 도구를 추가했다. OpenAI API·모델 교체·운영 설정 변경은 하지 않았다.
챕터 API·작업 결과 저장·프론트엔드 연결은 이번 범위에 포함하지 않는다.

## 구현과 자동 검증

관련 테스트 **58개 통과**. 전체 테스트 모음은 실행하지 않았다.
실행 명령은 개발 문서의 챕터 시험 명령과 같다.

- 실제 서버 템플릿으로 입력·출력 토큰 합계 2048을 검사한다.
- 모델은 시작 자막 ID·한국어 제목·설명만 생성한다. 구간 시각과 포함 자막 ID는
  원본에서 계산하며, 묶음 경계는 별도 호출로 같은 주제의 연속인지 판정한다.
- 잘못된 JSON·알 수 없는 ID·중복·역전·첫 자막 누락·추가 필드·한국어 누락을 거부한다.
- 정상 종료 이외의 출력과 전송 오류는 최대 2회 시도한다. 원시 출력·종료 사유·오류·시간을 보존한다.
- 빈 입력, 단일 자막 초과, 경계 병합의 예산 초과, 추론 잠금 해제와 기존 보고서 보호를 검사한다.
- 실제 로켓·미적분의 저장 자막을 모의 HTTP 서버로 처리해 원본 전체 근거 연결을 검사한다.
  모의 모델의 출력은 사람이 정한 테스트 응답이며 자동 생성된 실제 목차가 아니다.

## 실제 로컬 모델 시험

이전 시도에서는 Docker 데몬 연결과 앱 실행이 실패했다. 사용자 요청 후 다시 확인했을 때
`/Applications/Docker.app`이 있었고 기존 backend·translator가 healthy 상태로 실행 중이었다.
Colima는 실행 중이 아니었다. 이번 시험에서 Docker 설치·모델 다운로드·운영 서버 재시작은 하지 않았다.

미완료 작업이 없음을 확인하고 기존 backend 이미지로 일회용 평가 컨테이너를 실행했다.
코드는 읽기 전용으로 연결하고 `/reports`만 평가 디렉터리에 쓰도록 했다. 기존 내부
네트워크의 translator에 요청했으며 호스트 포트·모델·CPU·메모리 설정은 바꾸지 않았다.
원본 영상 업로드·STT를 다시 실행한 시험이 아니라 저장된 17개·43개 자막을 분석한 시험이다.

| 저장 자막 | 챕터 수 | 처리 시간 | 생성·병합 호출 | 재시도 | 근거 연결 |
| --- | ---: | ---: | ---: | ---: | --- |
| 로켓 | 5 | 58.144초 | 3 | 0 | 17/17 |
| 미적분 | 8 | 125.233초 | 7 | 0 | 43/43 |

모든 호출이 정상 종료했고, 각 자막이 원래 순서대로 정확히 한 번 포함되는지 독립적으로 검사했다.
각 챕터의 시작·종료 시각이 참조 원본과 같고 시작 시각이 증가하는지, 평가에 기록한 구현
해시가 현재 파일과 같은지도 확인했다. **구조·참조 검증 성공이며 의미 정확도 합격 판정은 아니다.**

### 실제 시험에서 발견해 수정한 문제

1. 최초 버전은 로켓을 9개로 과도하게 나누고 미적분에서 6개 제한을 어긴 8개 항목을 출력했다.
   동일 설정의 두 번째 시도도 같은 오류를 냈다. [최초 결과](chapters-real-261112.json)
2. 개수를 3개로 제한하고 JSON 스키마를 추가했지만 `response_format`의 전송 구조가 맞지 않아
   스키마가 빈 객체로 취급됐다. 로켓 11개·미적분 묶음 4개 출력으로 검증에서 거부됐다.
   [전송 구조 수정 전 결과](chapters-real-v2-261112.json)
3. 실제 서버 파서에 맞게 `response_format.json_schema.schema`로 수정한 뒤 짧은 요청으로
   스키마가 지정한 값만 생성하는 것을 확인했다. 로켓은 5개가 반환됐으나 미적분의 세 번째
   묶음에서 연결 발언을 생략해 첫 ID 검사가 실패했다. [첫 ID 고정 전 결과](chapters-real-v3-261112.json)
4. 서버가 지원하는 고정 배열 항목 형식으로 묶음의 첫 자막 ID를 강제했다. 후속 항목은
   현재 묶음의 나머지 ID만 허용하고 순서·중복은 코드에서 계속 검사한다. v4에서 두 자막 모두
   재시도 없이 통과했다. 기존 번역 요청에는 이 출력 스키마를 적용하지 않는다.

실패 자료는 삭제하거나 성공 결과로 덮어쓰지 않았다. 검증을 완화하거나 자막을 잘라 성공 처리하지 않았다.

### 실행 환경과 자원 관측

- Docker VM: Linux aarch64, 8 vCPU, 메모리 6,210,043,904바이트.
- translator: 8CPU·4,000,000,000바이트 한도, 문맥 2048, 기존 Q4_K_M 모델.
- backend: 4CPU·2,500,000,000바이트 한도. 이번 시험에서 STT는 실행하지 않았다.
- 평가 컨테이너: 기존 backend 이미지, 4CPU·512MiB, 읽기 전용 루트와 64MiB 임시 공간.
- 이미지: backend `sha256:bb4123b6e81856a0f40156553f55c12388dec2780ee3c1d576b4903de7878017`,
  translator `sha256:c8113a17ae624ea486e280719c1f9ee5bd62d972d5fe589aad6c3e62c58bb140`.
- 최종 실행 중 단일 `docker stats` 표본: backend 82.51MiB, translator 2.816GiB,
  평가 컨테이너 27.95MiB. 표본을 peak·호스트 전체 메모리·STT 동시 실행 요구량으로 해석하지 않는다.
- 시험 후 실제 모델 파일을 `sha256sum`으로 별도 검사하여
  `3605803b982cb64aead44f6c1b2ae36e3acdb41d8e46c8a94c6533bc4c67e597`이
  고정 명세와 일치함을 확인했다. 평가 도구 자체는 파일명만 검사하므로 이 검사는 별도 확인이다.
- 전후 두 운영 서버는 healthy, OOM false·재시작 0. 일회용 평가 컨테이너는 종료 후 제거됐다.
- v4는 각 영상 한 번의 관측값이며 반복 평균이나 이전 후보 대비 속도 개선 검증이 아니다.

## 내용 검토와 남은 문제

반환된 한국어와 저장된 영어 원문을 대조했다. 실제 음성·판서와 대조한 정답 평가는 하지 않았다.

- 로켓 25.96초 챕터 설명은 원문의 불명확한 STT 수식을 문장으로 재구성하여 연산 관계를
  잘못 설명할 수 있다. 수식 재구성 금지 지시만으로 의미 오류를 막지 못했다.
- 로켓 171.53초부터 끝까지의 제목·설명은 '방정식 정리'에 머물러 질량 감소·속도 감소와
  썰매 정지라는 핵심 결론을 충분히 반영하지 못한다.
- 미적분 153.55초 설명은 단원 끝에 계산할 예정이라는 예고를 실제 계산 과정을 다루는 것처럼
  요약한다. 206.53초 제목 '모든 함수의 미분 가능성'은 강의의 구어적 표현을 과도하게 일반화한다.
- 미적분의 기하학적 해석 관련 항목이 214.96·230.38·251.11초에 나뉘어 있어 주제 단위
  탐색 관점에서 추가 병합이 필요하다. 형식 제한은 의미상 과분할을 해결하지 않는다.

따라서 실제 생성·참조 연결은 확인했으나 학습자가 그대로 신뢰할 수준의 목차로 판정하지 않는다.
다음 작업은 내용 누락·예고와 본문 구분·수식 재구성·주제 과분할을 개선하고 실제 영상과 대조하는 것이다.
API·화면 연결 전에 이 품질 검증이 필요하다. 커밋은 수행하지 않았다.
