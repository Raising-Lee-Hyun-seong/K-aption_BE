# OpenBLAS 대표 6문장 비교 (2026-10-29)

3단계 결과: OpenBLAS ON을 적용하지 않는다. 동일 조건 OFF보다 평균 1.98배 느려
19문장 및 전체 영상 시험으로 확대하지 않았다. 운영 설정은 유지했다.

## 실제 측정

| 이미지 | 첫 실행 | 두 번째 실행 | 평균 | 실패 / 측정 번역 수 |
| --- | ---: | ---: | ---: | ---: |
| 운영 공식 이미지 복제 | 22.969초 | 21.871초 | 22.420초 | 0 / 12 |
| 새 BLAS OFF | 22.622초 | 22.358초 | 22.490초 | 0 / 12 |
| 새 BLAS ON | 45.693초 | 43.383초 | 44.538초 | 0 / 12 |

순서는 공식 → OFF → ON → ON → OFF → 공식이다. 총 36개 측정 번역 모두 한 번에
반환되어 재시도는 없었다. 각 조건의 두 반복 출력은 6개 모두 같았다.
공식 이미지와 OFF의 출력도 같고 평균 시간 차이는 약 0.3%였다.
측정 시간은 저장된 원문을 기존 번역 서비스로 재생한 합계이며 HTTP 토큰화·생성·검증을
포함한다. 업로드·STT·문장 묶기·자막 생성·모델 로딩·사전 워밍업은 제외한다.
이 수치를 전체 영상 처리 시간으로 해석하지 않는다.

| 입력 처리 | 11.861초 | 33.025초 |

주된 차이는 입력 처리에서 발생했다. ON의 출력이 일부 달라 생성 토큰 수도 8개 많았다.
따라서 생성 시간 차이를 동일 출력 길이의 순수 연산 속도 차이로 단정하지 않는다.
OpenBLAS 내부의 정확한 연산별 비용은 프로파일링하지 않았다.

## 실행 조건과 BLAS 확인

- 네이티브 Mac ARM64 Docker, VM 8 vCPU와 약 6GB 메모리.
- CPU 8개, threads와 threads-batch 각각 8, 번역 컨테이너 메모리·스왑 상한 각각 4GB.
- 운영과 동일한 Qwen3-4B-Instruct-2507 Q4_K_M GGUF 및 SHA256 확인.
- 기존 문맥·용어집·수식 보호·존댓말 지시·검증·최대 두 번 시도 설정을 그대로 사용.
- `--device none`, GPU layers 0, KV·연산 오프로딩 차단, `--no-repack` 등 기존 인자 유지.
- 프롬프트 캐시 활성화, seed 0과 기존 결정적 생성 설정 유지.
- 매 실행마다 새 서버를 생성하고 같은 캐시 비활성 워밍업을 한 뒤 측정했다.
- 운영 서버는 재생성하지 않았다. 별도 내부 네트워크에 비교 서버 한 개씩만 띄웠다.
- 원문 인덱스 `0, 2, 3, 12, 16, 18`: 일반 설명, 변수 분리·적분, 긴 수식,
  적분·분수, 긴 물리 설명, 별도 선형대수 문장.

ON에서 모델 로딩 및 번역 요청 후 BLAS 계산 그래프 배정을 진단 로그로 확인했다.
해당 준비 확인은 진단 로그를 켰으므로 정식 시간 비교에서 제외했다.
측정 실행에서는 진단 옵션을 끄고 동일 인자·스레드를 사용했다.
단순 라이브러리 등록만으로 BLAS가 사용됐다고 판단한 결과가 아니다.

## 번역 품질

모두 기존 형식·용어·수식 검사에 통과했지만 ON의 품질 개선 근거는 없다.
ON은 두 번 모두 선형대수 문장에서 `좋아요` 대신 `좋아`를 출력했다.
문장 끝이 존댓말이어도 내부 반말을 현재 검사가 놓친 사례다.
엔진 비교 범위를 유지하기 위해 이번 작업에서 프롬프트·검증 로직을 변경하지 않았다.

긴 수식 문장에서는 ON이 `mr dvr = dmru`를 `mR d vR = d mR u`로 표기하는 등
차이가 있었다. 원문에 이미 모호한 STT 수식 표현이 있으므로 이를 정확도 상승으로
평가하지 않는다. 원시 번역은 JSON에 모두 보존했다. 별도 정답 번역으로 점수화하거나
블라인드 평가한 결과가 아니며, 6개 입력을 넘어선 품질을 보장하지 않는다.

## 메모리·실패·한계

측정 컨테이너 cgroup peak는 OFF 약 389MB, ON 약 495MB에서 500MB였다.
동일 GGUF 볼륨과 기존 운영 컨테이너가 파일 페이지 캐시를 공유하므로 이 값은
독립 실행 시 전체 모델 메모리 요구량이 아니다. 파일 페이지가 다른 cgroup에
청구될 수 있어 RAM 16GB Windows 요구량 검증으로 사용할 수 없다.
각 측정에서 OOM kill 0, 컨테이너 재시작 0이었다.

처음 준비 확인은 번역 성공 후 진단 로그에 포함된 불완전 UTF-8 토큰 조각 때문에
로그 수집기가 실패했다. 해당 결과와 오류를 보존하고, 로그 디코딩만 수정한 새
수집기로 다시 시작했다. 번역 JSON에는 대체 문자 처리를 적용하지 않았다.
실패한 준비 확인과 재실행 준비 확인은 모두 정식 비교에서 제외했다.

실행 전 활성 비동기 작업 0을 확인했다. 호스트 발열·주파수·다른 프로세스 부하는
고정하지 않았으며 조건당 2회 시험이다. AMD64와 Windows는 미검증이다.
STT·작업 API·SSE·자막 회귀 시험 및 전체 테스트 모음은 이번에 실행하지 않았다.
