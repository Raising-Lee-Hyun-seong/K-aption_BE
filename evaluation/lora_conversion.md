# KoreanLM LoRA 다운로드·변환 점검

점검일: 2026-10-05.

**공식 고정 리비전의 LoRA B 행렬 64개가 모두 0이다. 이 파일은 기반 모델에 학습된 변화를 추가하지 않는다.** 변환은 완료했지만 이 어댑터의 적용만으로 기존 오역이 개선된다고 기대할 근거는 없다.

## 실제 파일 확인

- 저장소: `quantumaikr/KoreanLM-LoRA`
- 리비전: `1447f2ae33e32cb8af610758b90adda0c05670a2`
- 원본: `models/koreanlm-lora-peft/adapter_model.bin`, 8,434,381바이트
- 원본 SHA256: `f7f1707df4e86b215ad34347ea3dc9a508c7b46d6f15abf296cd556245aa98fb` (공식 값과 일치)
- 변환 결과: `models/koreanlm-lora-mlx/adapters.safetensors`, 8,402,400바이트
- 변환 SHA256: `e23b174ba405dda35ac3b9b567c94c8e4dc3ca584bc6f8319660aee2739eca58`
- 32층 × q_proj/v_proj × A/B = 128개 float32 텐서. PEFT A는 (4, 4096), B는 (4096, 4)이며 MLX에는 각각 전치해 저장했다. rank 4, alpha 16에 따라 MLX scale은 4.0이다.

A 행렬 64개는 모두 0이 아닌 값을 포함하며 비영 원소 합계는 1,048,576개다. B 행렬 64개는 비영 원소가 0개다. 따라서 추가 계산 `scale * B @ A`는 모든 입력에서 0이다. 학습 미수행·저장 오류 등 원인은 확인하지 않았으며, 다른 리비전의 상태를 뜻하지 않는다.

## 검증 범위

- 원본 두 파일의 SHA256을 확인한 뒤 `torch.load(weights_only=True)`로 읽었다.
- 키·층·모양·자료형·유한값·누락·중복을 검사하고 저장 파일을 다시 읽었다.
- 64개 투영의 PEFT 방식 PyTorch CPU 계산과 변환 후 행렬 계산이 일치했다. 실제 MLX CPU 파일 로딩·행렬 계산도 64개 모두 최대 절대 차이 0이었다.
- 실제 파일은 B가 모두 0이므로 이 수치 일치만으로 전치·배율의 정확성을 입증할 수 없다. 별도의 비영값·비정방형·GQA 테스트에서 전치·배율·투영 매핑을 확인하고 잘못된 배율·투영, 불완전한 키와 비정상 설정을 거부했다.
- 전체 회귀 테스트 66개 통과. 영값 B 전체/일부 여부를 구분하는 테스트를 포함한다.

전체 기반 모델을 로드하거나 번역하지 않았다. 기반 가중치 리비전·전체 모델 추론 호환성·번역 품질은 미검증이다. API 모델과 로더는 변경하지 않았다. 원본 및 변환 가중치가 약 16.06MiB 추가됐으며 기존 대용량 캐시는 삭제하지 않았다. 모델 파일은 Git 제외 대상이다.

## 재현

```bash
.venv-api/bin/python scripts/prepare_koreanlm_lora.py --download --verify-mlx
```

체크섬이 일치하는 원본은 재사용한다. `--verify-mlx`를 생략하면 MLX 런타임 없이 PyTorch CPU로 변환 수치를 검사한다. 상세 결과는 [lora_conversion.json](lora_conversion.json)에 기록한다.
