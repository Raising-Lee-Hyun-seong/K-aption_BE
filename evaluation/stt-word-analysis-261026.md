# 배치 STT 단어 시각·자막 분할·전체 API 비교

2026-10-26. **단어 시각 복원과 STT 추론 단축은 확인했지만, 품질을 유지한 전체 API의 안정적인 단축은 확인하지 못했다. 운영 설정에는 적용하지 않았다.**

2026-11-03 정리: 미채택 단어 분할 도우미·평가 도구·관련 테스트는 실행 경로에서
제거했다. 아래 경로와 검증 내용은 당시 평가의 기록이며,
[구현·테스트 원문과 SHA256](retired-experiment-sources-261103.json)에 보존했다.
원시 JSON과 SRT/VTT 결과는 기존 파일 그대로 유지했다.

## 시험 조건

- Apple Silicon Mac, 호스트 RAM 16GB, Linux ARM64 Docker, VM 8 vCPU·6,210,043,904 bytes.
- 동일한 프로젝트 영상 `MIT8_01F16_W06PS01-2_360p.mp4`, 212.5866875초.
- STT는 Whisper Small CPU INT8·beam 5·영어·VAD·4 CPU·기존 메모리 제한 특징 추출기다.
- 후보는 배치 2·`without_timestamps=True`·`word_timestamps=True`를 사용했다.
  구간 시각 토큰 생성 대신 단어 정렬 결과로 자막 시각을 구성한다.
- Qwen 모델·GPU 비사용·8 CPU·프롬프트·용어집·복원/검증·재시도 상한은 유지했다.
- 진행 중인 작업이 없는 상태에서 운영 서비스와 분리된 평가 컨테이너를 사용했다.
  STT/평가 API의 메모리와 memory+swap 상한은 각각 2,500,000,000 bytes였다.
- Windows amd64, 실제 5분 영상, 90분 입력과 장시간 동시 요청은 시험하지 않았다.

## 1. 단어 정렬을 켜도 빠른 STT 경로가 유지됐다

일반 → 후보 → 후보 → 일반 순서로 실행했다. 같은 12초 워밍업 후 전체 영상을 전사했다.
아래 시간은 STT 생성·단어 정렬·결과 수집이며 모델 로딩·디코딩·워밍업·자막 재분할·번역은 제외한다.

| 경로 | 첫 실행 | 두 번째 실행 | 평균 | 기준 자막 단어 차이 |
| --- | ---: | ---: | ---: | ---: |
| 기존 일반 STT | 28.375초 | 26.350초 | **27.363초** | 각 51 / 369단어 |
| 배치 2 + 단어 시각 | 15.623초 | 15.593초 | **15.608초** | 각 52 / 369단어 |

추론 시간은 평균 약 **42.96%** 짧았다. 후보 두 실행의 원문·단어 시각은 같았다.
원시 구간 7개에 단어 345개가 있었고, 영시간 단어 1개를 삭제하지 않고 인접 조각에 포함했다.
단어 간 역전·범위 밖 시각과 겹침은 실제 결과에서 관측되지 않았다.

단어 차이 51→52는 의미 정확도가 낮아졌다는 비율로 환산하지 않았다.
기존 대비 `prime of` 추가, `going to`→`gonna`, `all right`→`alright`, `2m0`→`2 m0` 등이 있었다.
`prime of equal vr of t`는 기존 공식 자막에도 있지만 알려진 불확실한 수식 구간이다.
따라서 이를 올바른 수식 복원으로 인증하거나 임의 보정하지 않았다.
이번 후보에는 이전 타임스탬프 토큰 생성 배치에서 관측한 함수 발언·질량 설명의 통째 누락은 없었다.

자료: [원시 STT·단어 시각·실행 소스·전사 차이](stt-word-alignment-261026.json).

## 2. 자막 시각 복원과 원문 보존

`app/services/stt_words.py`의 `split_aligned_segments`를 추가했다.
운영 STT에서는 호출하지 않으며 평가 API에서만 사용했다.

- 원시 구간의 text와 단어를 대조하고, 단어·숫자·변수·문장부호와 순서를 유지한다.
- 음성 범위 안의 유한 시각만 허용한다. 단어 누락·역행·원문 불일치는 거부한다.
- 문장·무음·18초·350자 상한에 따라 34개 조각으로 나눴다.
- 붙어 있는 숫자·변수 토큰과 겹치는 단어 사이에서는 자르지 않는다.
- 누락된 시각을 만들거나 영어를 고쳐 넣지 않는다.
- 기존 문장/수식 묶기 파이프라인을 거치면 번역 단위는 26개였다. 기존 일반 경로는 17개다.

26개 요청의 추가 비용을 보기 위해 선택적 `pack_sentences=True`도 시험했다.
인접 조각을 같은 18초·350자·2초 무음 상한 안에서 묶고 질문 경계는 유지한다.
원문은 그대로이며 이 후보는 STT 조각 15개, 최종 번역 단위 14개였다.
질문·수식·숫자를 삭제해 요청 수를 줄이지 않았다.

## 3. 실제 전체 영상 HTTP API

분리된 API 컨테이너와 내부 HTTP 클라이언트로
`POST /api/v1/transcriptions?language=en`에 원본 영상을 업로드했다.
각 API 컨테이너는 STT 미로드로 시작했고 같은 캐시 비활성 Qwen 워밍업을 했다.
요청 시간에는 업로드·STT 로딩/전사·단어 분할·문장 묶기·번역·검증·응답이 포함된다.
후보에는 원시 정렬 감사 JSON 저장도 포함된다. Docker 빌드·서버 준비 시간은 제외한다.

| 실행 순서 / 경로 | 전체 HTTP | STT | 번역·검증 | 번역 반환 |
| --- | ---: | ---: | ---: | ---: |
| 1. 기존 | **93.438초** | 27.598초 | 65.768초 | 17/17 |
| 2. 단어 시각·문장 분할 | **89.909초** | 17.088초 | 72.769초 | 26/26 |
| 3. 단어 시각·인접 문장 묶음 | **87.554초** | 17.596초 | 69.921초 | 14/14 |
| 4. 기존 재확인 | **84.374초** | 28.818초 | 55.490초 | 17/17 |

첫 비교에서는 3.529초·3.78% 짧았지만, STT 절감분 대부분을 늘어난 번역 비용이 사용했다.
문장을 묶어 요청을 줄인 후보도 다음 기존 실행보다 3.180초·3.77% 느렸다.
기존 두 실행 자체가 약 9.064초 달랐으므로 3초 수준의 차이를 안정적인 개선으로 채택하지 않는다.
호스트 열·클럭·부하를 통제하지 않았고 각 전체 API 후보는 1회다.
이전 날짜의 약 110초 측정과 직접 비교해 이번 변경의 개선량으로 제시하지 않는다.

모든 요청은 HTTP 200, 반환 실패 0이었다. 그러나 다음 품질 문제가 있었다.

- 문장 분할 후보의 원문은 상수·앞 배치·분수 설명뿐인데,
  번역이 앞 문맥의 `우리는 m을 다른 쪽으로 옮깁니다`까지 다시 출력했다.
- 긴 무음/상한 경계에서 `And then we can immediately do`와 `this here over 2m0`가 나뉘어
  각각 불완전한 한국어 조각이 됐다.
- 묶음 후보는 방정식을 가리키며 `그는 지금 적분할 수 있는 방정식입니다`라고 했다.
- 불확실한 초기 조건 발언에 함수 값 설명을 덧붙였으며, 문장 내부에 `좋아`도 남았다.

따라서 반환 성공을 의미·문법·존댓말 정확도 100%로 보지 않는다.
검증을 완화하거나 잘못된 문장을 기계적으로 잘라 성공 처리하지 않았고, 두 후보 모두 미채택했다.

자료: [문장 분할 실제 API](stt-word-api-261026.json), [문장 묶음 실제 API](stt-word-packed-api-261026.json).

## 4. 메모리·자막·테스트

단어 정렬 STT 후보의 두 실행 cgroup peak는 1,456,168,960·1,437,102,080 bytes였다.
전체 API의 cgroup peak는 기존 1,382,678,528 bytes, 문장 분할 1,435,500,544 bytes,
문장 묶음 1,498,034,176 bytes, 기존 재확인 1,459,597,312 bytes였다.
평가 컨테이너의 OOMKilled는 false·재시작은 0이었다.
이 값은 해당 컨테이너 범위이며 Qwen·운영 backend·호스트 전체 RAM을 합한 측정이 아니다.

실제 HTTP 응답을 기존 `render_subtitles`로 한영 SRT/VTT에 내보내고
시각 범위·양의 길이·정렬·겹침 없음·cue 개수와 원문 보존을 확인했다.
이것은 **로컬 내보내기 검증**이며 이번에 작업 API/SSE/자막 다운로드를 다시 실행한 것은 아니다.

- 기존: [SRT](stt-word-baseline-261026.srt) / [VTT](stt-word-baseline-261026.vtt), 17개.
- 문장 분할 후보: [SRT](stt-word-aligned-261026.srt) / [VTT](stt-word-aligned-261026.vtt), 26개.
- 문장 묶음 후보: [SRT](stt-word-packed-261026.srt) / [VTT](stt-word-packed-261026.vtt), 14개.

후보 자막은 품질 문제를 보존한 평가 자료이며 권장 출력으로 제공하는 것이 아니다.
단어 분할·원문 대조·토큰 경계·겹침·손상 시각·질문/시간/문자 상한과 관련 자막 회귀만 테스트했다.
전체 테스트 모음은 실행하지 않았다. 최종 실행 개수와 파일 해시는 [집계](stt-word-summary-261026.json)에 있다.

초기 두 호스트 공개 포트 준비 확인은 완료되지 않아 시간 자료에 포함하지 않았다.
위 비교는 이후 내부 네트워크 클라이언트에서 모두 완료한 요청만 사용한다.
초기 접속 문제를 모델 속도·메모리 실패로 분류하지 않는다.
기존 평가 자료는 보존했고 운영 STT·프롬프트·모델·CPU 프로필을 변경하지 않았다.
커밋·push하지 않았다.
