# 수식 별칭·출력 검증과 Qwen3 수학 표현 보완 결과

보고 기준일: 2026-10-18. **공통 검증은 정상 수식 별칭을 허용하고 관찰된 언어 혼입을 재시도로 넘겼다. v3 강의 평가의 의미 보존은 28/36이었지만 새 번역 미제공과 썰매 오역이 남아 API 모델·프롬프트 교체는 보류한다.** 단일 Codex 원문 대조 판정이며 독립 사람·전문가 검수 전이다.

## 실제 API에 적용되는 변경

- `M_r`, `v_r`, `d_m_r`, `m_0` 등 지원 변수의 밑줄 표기를 기존 공백·붙임 표기와 같은 기호로 검사한다. 계수 변경·변수 누락·긴 식별자의 부분 일치는 계속 거부한다.
- `이전 영문 맥락`, `Previous English context:` 표식을 생성 중 발견하면 조기 종료하고 기존 정책대로 재시도한다.
- 원문에 없는 연속 키릴·가나·한자 문자 어구를 `unexpected_script`로 거부한다. 원문에 있는 같은 어구, 단일 수식 문자·그리스 문자, 한글 바로 뒤 괄호 한자 병기는 허용한다. 두 글자 미만·다른 문자권·문맥상 잘못된 외국어 인용까지 판별하는 일반 언어 분류기는 아니다. 허용하지 않는 한자 병기 형태 등은 오탐할 수 있다.

API의 모델·프롬프트·28개 용어집과 응답 계약은 유지한다. 실패는 기존과 같이 한 번 재시도하고 구간별 `translation_failed`로 전달한다. 이 공통 검증 변경은 서버 재시작 후 적용된다.

기존 출력 재검사에서 용어 보완 조건의 `并且`와 강의의 `равно`는 거부됐으며, 정상 `M_r`의 `missing_math_symbol` 오탐은 해소됐다. 기존 기준·관계 보완 22문장에는 새 문자 검사에 걸리는 출력이 없었다. 이는 확인한 저장 출력에 한정한 점검이다.

## 같은 강의 36구간 비교

[사전 계획](qwen-hardening-plan.md)에 따라 STT 단어·문장 묶음·시각은 변경하지 않았다. 기존 로컬 Qwen3 4B Instruct 2507 4bit, 시스템 메시지의 앞 영어 문맥 256자, 최대 128토큰, 문맥 없는 재시도 1회, 기존 API 용어 검사 조건을 유지했다. v3는 평가 전용 추가 용어와 수학 지시만 바꿨다. 추가 용어를 필수 출력으로 강제하는 검증은 넣지 않았다.

| --- | ---: | ---: | ---: |
| 자동 검증 수락 | 34/36 | 34/36 | 35/36 |
| 의미 보존 | 26/36 | 26/36 | 28/36 |
| 실패 | 7 | 6 | 3 |

각 조건은 한 번 실행했다. 속도·일반 정확도 개선율로 해석하지 않는다. 저장 STT를 재사용해 디코딩·실제 음성 인식·전체 API 시간은 측정하지 않았다. 모델·출력·입력·구현 해시와 원시 생성 시도를 결과에 보존했다.

### 검증 보완의 효과

v2에서 stt-23의 첫 출력에 있던 러시아어 `равно`를 거부했고 재시도에서 `mR' = m of vR`라는 표기를 얻었다. 이외 35구간의 반환 번역은 이전 v2와 같았다. 해당 원문의 함수 인자는 여전히 불명확해 판정을 실패에서 미판정으로 바꿨고 의미 통과 수는 늘리지 않았다.

### v3에서 개선되거나 남은 점

[v3 평가 용어](physics_glossary_additions_v3.json)에 sled·integrated/integrating·prime/primes를 추가했다. 수학 문맥에서 over의 나눗셈, 인자의 위치 설명, 프라임과 변수 표기 보존도 지시했다. 변경을 묶었으므로 어느 단일 요소의 효과인지는 분리하지 않는다.

- stt-14는 vR와 프라임을 보존한 번역을 제공해 이전 번역 미제공을 해소했다.
- stt-26은 Integrated를 통합 대신 적분으로 번역했다.
- stt-28은 `over 2m0`를 2m0로 나누는 관계로 옮겼다.
- **stt-25는 회귀했다.** 두 시도 모두 `vR - v0 = u1 / m`만 출력했다. 주어진 수식은 유지했지만 한글이 없어 형식 검사에서 거부됐으며 사용자에게 번역이 제공되지 않았다.
- stt-9는 수학적 인자 위치를 `그는 앞서 나온다`로 옮겨 여전히 엄격한 의미 통과에 미달한다.
- stt-35는 썰매를 `씰`로 옮겼다. 평가용 용어 지시만으로 대상 보존을 보장하지 못했다.
- stt-17은 프라임 표기를 제공했지만 `2/to` 등이 불명확한 파편이어서 실패에서 미판정으로 옮겼다. 이를 의미 개선으로 세지 않았다.

v3의 미판정은 stt-1·8·17·23·27이다. 수식의 명확한 누락·오역이나 출력 미제공은 원문 문제와 별도로 실패로 기록한다. 문맥에 따라 `do that`을 적분 작업으로 풀어 옮기는 정상적인 대명사 해소는 허용한다. 판정 기준과 각 원문·출력·근거는 아래 파일에 있다.

- 검증 보완 v2: [실행](qwen-hardening-v2.json), [판정](qwen-hardening-v2-review.json)
- 보완 v3: [실행](qwen-hardening-v3.json), [판정](qwen-hardening-v3-review.json)
- 이전 기준: [실행·판정 비교](qwen-refinement-comparison.md)

## 22문장 회귀

v3로 기존 공식 자막 10문장·합성 물리학 12문장을 두 번 실행했다. 문맥·재시도·정리·조기 중단 없이 최대 256토큰, 온도 0, 입출력 합계 2048토큰을 사용했다.

의미 보존은 **21/22**, 부분 보존은 1개로 이전 관계 보완 조건과 같았다. 남은 사례는 u를 포함한 등식 연결이다. 두 회차 출력은 22개 모두 같았다. 자동 형식·기호·용어 진단은 22/22였으며 의미 정확도 22/22를 뜻하지 않는다. 생성 시간은 25.44초·25.75초, MLX 최고 할당량은 2.75GB였다.

단문에서는 sled가 썰매로 번역됐지만 강의 문맥이 있는 stt-35에서는 씰로 번역됐다. 단문 통과를 실제 강의 품질로 일반화할 수 없다는 사례다.

[실행](qwen-hardening-cases.json), [22문장 판정](qwen-hardening-cases-review.json)에 원문·원시 출력·프롬프트·판정 근거를 보존했다. 알려진 오류로 개발한 조건이라 새 강의나 독립 검증 결과가 아니다.

## 검증과 후속 작업

회귀 테스트 94개를 통과했다. 변수 별칭의 오탐·누락, 외국 문자 검사 예외, 언어 혼입 후 실제 재시도와 문맥 제거를 검증했다. 모델 평가는 별도 로컬 추론으로 실행했다. 기존 평가 결과는 덮어쓰지 않았고 커밋하지 않았다.

다음 품질 작업은 끊긴 STT 등식 경계·수식 전용 출력 정책·문맥에 따른 대상 보존이다. 경계를 바꾸면 36구간과 일대일 비교할 수 없으므로 원본 인덱스·시각으로 다시 정렬해 평가해야 한다. 이후 개발에 쓰지 않은 강의와 사람 검수로 모델 적용 여부를 판단한다. 작업 ID·진행률 API 같은 BE 기능 개발은 이 품질 검수와 별도로 진행할 수 있다.
