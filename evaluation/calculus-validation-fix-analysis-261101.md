# 미적분 번역 검증 오탐 수정 (2026-11-01)

`work out` 문맥과 숫자 검증만 수정했다. 모델·추론 서버·스레드·문장 묶기·
문맥 전달·재시도 상한은 유지했다. 기존 평가 결과와 테스트 데이터도 보존했다.

## 수정 내용

- 계산을 뜻하는 `work out`, `work this out`, 제한된 계산 목적어의 `work … out`에서
  `work=일`을 프롬프트와 필수 용어 검사에서 제외한다. 같은 발언의 실제 물리적
  `work`와 `work that is carried out` 같은 관계절은 계속 검사한다.
- `first one`은 `첫 번째`·`첫째`·숫자 서수로 검사한다. `this one is` 등의 명시적
  지시 표현을 수량 1로 강제하지 않는다. `one kilogram`, `one of`, `one more`는
  기존 수량 검사를 유지한다.
- 영어 `minus 1`·`negative 1`, 한국어 `마이너스 1`·`음의 1`, `-1`을 같은 값으로
  비교한다. 부호는 바로 뒤 수량에만 적용하고 `다음의`·`non-negative`는 제외한다.
- `9th`, `10th`와 숫자로 옮긴 지수를 같은 값으로 비교한다. `2y0`, `3x` 등의
  x·y 계수도 추출하여 대명사 예외가 실제 계수 변경을 허용하지 않도록 했다.
- `one or two`, `question or two`에만 `한두`를 허용한다. 정확한 두 개를 한두 개로
  바꾸거나 부호·계수·서수를 바꾸는 결과와 원문에 없는 숫자는 계속 거부한다.

수정 전 12개 거부에서 수정 후 0개 거부로 바뀌었다. **실제 모델이 실패했다가 복구한

않았고, PDF의 22개 화면만으로 팀원이 보고한 실패 27개의 복구율을 계산할 수 없다.

## 실제 프로젝트 영상 API 결과

Mac ARM64 Docker에서 원본 영상 두 개를 각각 한 번씩 순차 업로드했다.

| 영상 | 이전 반환 | 수정 후 반환 | 생성 시도 전후 | 이전 전체 요청 | 수정 후 전체 요청 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 로켓 212.587초 | 17/17 | 17/17 | 17 → 17 | 105.182초 | 227.689초 |
| 미적분 330.908초 | 42/43 | 43/43 | 45 → 44 | 124.698초 | 180.530초 |

두 응답 모두 HTTP 200이며 번역 실패는 0개다. **반환 성공률은 의미 정확도 점수가 아니다.**
영어 원문·묶음 개수·타임스탬프는 두 영상 모두 이전 결과와 완전히 같다.
로켓의 한국어 17개도 모두 같다. 미적분에서 달라진 한국어는 아래 두 개뿐이다.

- 71.83초부터 79.21초: `And the first one is the geometric interpretation.`
  이전에는 두 번 `missing_number`로 거부됐다. 수정 후 첫 생성에서
  `첫째는 기하학적 해석입니다.`를 반환했다.
- 200.45초부터 206.53초: `work this out by the end of this unit.`
  `이 단위의 끝까지 이 일을 계산해 보세요.`에서
  `이 단위의 끝까지 이를 계산하여 해결하시기 바랍니다.`로 바뀌었다.
  `unit`의 강의 단원 의미를 여전히 `단위`로 옮기는 한계는 남는다.

| 영상 | STT 이전 | STT 수정 후 | 번역 이전 | 번역 수정 후 |
| --- | ---: | ---: | ---: | ---: |
| 로켓 | 33.112초 | 86.479초 | 71.656초 | 141.029초 |
| 미적분 | 39.292초 | 50.786초 | 80.160초 | 124.654초 |

이번 관측 시간은 모두 더 길어졌다. 속도 개선은 확인하지 못했다.
변경하지 않은 STT 시간까지 크게 달라졌으며, 기준 백엔드를 켠 채 별도 백엔드를
평가하여 메모리·페이지 캐시 조건도 다르다. 호스트 발열·주파수·배경 부하와 모델
페이지 상주 상태를 고정하지 않았으므로 증가분을 수정 코드의 비용으로 단정하지 않는다.
재시도 감소와 검증 결과의 개선은 실제 로그로 확인했지만, 처리 시간 단축을
판정하려면 같은 단일 백엔드 조건의 반복 비교가 필요하다.

## 환경과 재현 범위

- VM 8 vCPU, 메모리 6,210,043,904바이트. 백엔드 4CPU·2.5GB,
  번역기 8CPU·4GB. Qwen3-4B-Instruct-2507 Q4_K_M CPU 설정 유지.
- 기존 백엔드 이미지 위에 번역 코드 두 파일만 복사하여 평가했다.
  STT·API 라이브러리 버전은 기준 이미지와 동일하다.
  faster-whisper 1.2.1, CTranslate2 4.8.3, FastAPI 0.157.0,
  httpx 0.28.1, NumPy 1.26.4.
- 평가 이미지 `sha256:bb4123b6e81856a0f40156553f55c12388dec2780ee3c1d576b4903de7878017`.
  부모 이미지 `sha256:0571ff5bf3d350f6b0dff647ef3aece975e501fed1b1ed0e4632c2100e0fe2dd`.

## 로컬 실행 반영

영상 평가를 마친 뒤 검증한 이미지를 `kaption-backend:local`에 연결하고
`docker compose --env-file docker/cpu8.defaults up -d --no-deps --no-build backend`로
로컬 백엔드에 반영했다. 번역기 이미지와 8CPU 설정·모델·작업 볼륨은 유지했다.
두 서버는 healthy이며 적용된 번역 파일 두 개의 SHA256이 평가 소스와 같다.
STT 모델은 재시작 뒤 첫 요청에서 지연 로딩하므로 현재 health의 STT 로딩 값은 false다.
평가 컨테이너 두 개는 응답·로그 보존 뒤 삭제했다.
복구용 이전 이미지는 `kaption-backend:before-calculus-fix-261101`로 보관했다.
